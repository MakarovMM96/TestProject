# Формат .sai2 (что известно и как это используется)

Источники: [photopea/SAI2-specification](https://github.com/photopea/SAI2-specification),
[Wunkolo/libsai](https://github.com/Wunkolo/libsai) (`include/sai2.hpp`, `source/sai2.cpp`).
Все числа little-endian.

## Заголовок (64 байта)

| Смещение | Размер | Поле |
|---|---|---|
| 0 | 16 | `SAI-CANVAS-TYPE0` |
| 16 | 1 | флаги |
| 17 | 1 | флаги фона: `(x & 7) == 0` — прозрачный фон (превью в 4 канала, иначе в 3) |
| 18 | 2 | флаги |
| 20 | 4 | ширина холста |
| 24 | 4 | высота холста |
| 28 | 4 | разрешение печати (dpi) |
| 32 | 4 | N — число записей в таблице |
| 36 | 4 | id выбранного слоя |
| 40 | 16 | неизвестно |
| 56 | 4 | цвет фона (обычно `0xFF808080`) |
| 60 | 4 | `norm` / `vivd` / `deep` / `mult` / `ver1` |

## Таблица блоков (N × 16 байт, сразу после заголовка)

| Смещение | Размер | Поле |
|---|---|---|
| 0 | 4 | тип блока |
| 4 | 4 | id объекта (слоя) |
| 8 | 8 | абсолютное смещение блока в файле |

Блоки идут по возрастанию смещений. Первый начинается сразу за таблицей, поэтому
`N = (смещение_первого − 64) / 16`. Размер блока равен разности соседних смещений.

Типы: `hist` (история), `thum` (миниатюра jssf), `intg` (сведённое изображение),
`layr` (описание слоя), `lpix` (пиксели слоя), `fpix`, `mask`, `mpix`, `liwk`, `shap`, `pers`,
`text`, `grid`, `symm`.

## `layr`

```
0   "layr"    4  u32 id    8  8 нулевых байт
16  тип слоя: norm / fold / text / shap / liwk
20  4 × s32 (неизвестно)   36 u32 (неизвестно)
40  u32 число плиток в lpix
44  режим наложения (norm, scrn, over, …)   48 u32 непрозрачность 0..100   52 u32 флаги
56  параметры: (тег, u32 длина, данные)*, завершаются u32 0;  "name" — имя слоя
```

Что значение по смещению 40 действительно число плиток, программа проверяет на каждом файле
(`LayerTileCountConfirmed`) и пользуется им, только если оно совпало у всех целых слоёв.

## Пиксельные данные (`intg`, `lpix`, …): `dpcm`

```
"dpcm"
u32 длина[K]                         K = число плиток в блоке
для каждого ряда плиток:
    плитки ряда: u16 заголовок (старший байт = номер столбца X), затем строки
    u16 разделитель ряда (старший байт = число столбцов TilesX)
```

Плитка 256×256, крайние плитки обрезаны по размеру холста. В `intg` хранятся все плитки
(K = TilesX × TilesY). Для слоёв программа допускает и разреженную запись, где пустые плитки
пропущены, а позиции берутся из заголовков. Какая запись перед ней, определяется по самому файлу.

### Сжатие строки

Каждая строка плитки выровнена по байту. Для каждого канала (B, G, R, [A]) подряд записаны коды
разностей. Биты читаются начиная с младшего из 32-битных слов.

- `k` нулевых битов, `1`, бит `b` → код `op = 2k + b` (k ≤ 7)
- `op = 0` → разность 0
- `op = 1..14` → далее `op` бит значения `v` и бит знака: `|d| = (2^op | v) − 1`
- `op = 15` → далее 7 бит: серия из `n + 8` нулевых разностей (8..135)

Предсказание градиентное: `P = clamp(left + up − upleft, 0, 255)`, пиксель равен `P + d`.
Для первой строки плитки верхний ряд нулевой. Если фон непрозрачный, у `intg` 3 канала,
альфа равна 255.

Декодер побайтно точен: строка «съедает» ровно свои байты, а плитка ровно свою длину. Поэтому
любое повреждение нулями или обрывом надёжно обнаруживается, и по этому же свойству восстанавливается
размер холста.

## `thum`: `jssf`

```
u32 ширина, u32 высота, "jssf", u16 w, u16 h, u16 каналы (1|3),
64 байта таблицы квантования яркости, [64 байта цветности],
для каждого ряда блоков 8×8: u16 длина, данные энтропийного кодирования
```

Это поток baseline JPEG без маркеров. Программа добавляет стандартные таблицы Хаффмана и маркеры
RST между рядами и получает обычный `.jpg`.
